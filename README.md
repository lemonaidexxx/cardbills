# BillsBills

A private financial workspace with accounts, masked cards, statements, bank payments, personal collections, installments, reports, and Calendar reminders.

## Database release

The Supabase migration is described in [SUPABASE_MIGRATION.md](docs/SUPABASE_MIGRATION.md). GitHub stores the code, Cloudflare executes the protected application, and Supabase stores all live financial tables, labels/settings, import history, audit history, recovery journal, record baselines, and existing authentication. Google Sheets is backup data storage only, receiving daily one-way copies from Supabase. Normal data retrieval and saves do not depend on Sheets or Apps Script after verified cutover.

`DATA_BACKEND=supabase` enables the database runtime after the verified import. An unset value or `sheets` keeps the existing Apps Script backend during installation. The original Apps Script files are retained for rollback. They are not executed by Google in database mode.

Cloudflare uses a private SQLite-capable Durable Object to coordinate financial operations. The object does not persist ledger data; Supabase is authoritative. Existing owner, password, authenticator, session and request checks remain in front of financial access.

## Build and test

```sh
npm install
npm test
npm run check
npm run deploy
```

Node.js 22.12 or later is required. Wrangler is pinned to 4.102.0. Commit the package lock generated by installation. Wrangler's build command creates the scoped runtime modules from versioned source. Database installation and Google permissions are one-time owner-side steps; routine code updates deploy through GitHub.

Keep private import SQL, spreadsheet exports, Google service-account JSON, and credentials outside the repository. The supplied private migration kit contains the current ledger; this repository does not.

## Verification boundary

The migration implementation has local automated coverage. SQL installation, live RLS behavior, Cloudflare deployment, financial persistence and Google synchronization require the cutover checks in the migration guide. A successful code build alone does not establish a successful data migration.
